# Release notes — v1.0.2

**Date:** 2026-06-07
**Type:** Patch (bug fix)
**PyPI:** `taskchampion-mcp==1.0.2`
**Tag:** `v1.0.2`

---

## Summary

Fixes a silent data-loss bug where task fields declared in a file-provided
schema (preset, author example, or manually authored TOML) but not registered
as UDAs in `.taskrc` were silently dropped or produced cryptic TaskWarrior CLI
errors. Task creation and modification now fail early with a structured
`validation_error` and explicit registration instructions.

---

## Changes

### Fixed

**`create_task` / `create_subtask` / `modify_task` — schema UDA validation
against `.taskrc`** (`#33`)

Root cause: `load_schema()` accepted any field definitions from a TOML file
without checking whether non-builtin fields were registered as UDAs in
`.taskrc`. When the CLI received an unregistered field, it either silently
ignored the value or emitted an opaque error. Schemas auto-generated from
existing tasks were unaffected — they can only surface fields TaskWarrior
already holds.

Fix:

- `TaskwarriorCLI.udas() -> list[str]` — new method; runs `task _udas` and
  returns the list of registered UDA names (consistent with the existing
  `_projects` / `_tags` pattern).
- `schema.TASKWARRIOR_BUILTIN_FIELDS: frozenset[str]` — canonical set of
  built-in TaskWarrior fields that never require UDA registration.
- `schema.get_unregistered_uda_fields(schema, registered_udas) -> list[str]`
  — returns sorted list of schema field names that are non-builtin and absent
  from the registered UDA set. Analysis-generated schemas pass trivially.
- `ToolRegistry.__init__` caches `_registered_udas` from `task_cli.udas()` at
  startup and logs a warning if the loaded schema references fields not in
  `.taskrc`.
- `ToolRegistry.reload()` refreshes `_registered_udas` after rebuilding the
  task CLI.
- `create_task`, `create_subtask`, `modify_task` run a pre-flight check before
  calling the CLI. If any non-builtin field is not in `_registered_udas`, they
  return a `validation_error` with the message:
  `"Fields [...] are not registered as UDAs in .taskrc. Add
  'uda.<name>.type=string' ... to your .taskrc, then reload the server."`

---

## Upgrade notes

No breaking changes. No config changes required.

If you have a file-provided schema (preset or custom TOML) and tasks with UDA
fields are now being rejected with `validation_error`, it means those fields
were never making it into TaskWarrior. Add the missing UDA definitions to your
`.taskrc`:

```
uda.scope.type=string
uda.scope.label=Scope
uda.area.type=string
uda.area.label=Area
# ... repeat for each UDA in your schema
```

Then call `reload_configuration` (no restart needed).
